## 2. Stack, arquitectura y rutas clave
- Stack: `api/` Laravel 12 + Sanctum (Pest); `web/` React 18 + TS + Vite; `infra/` Terraform + Docker; `tests/k6/`; `docs/`. Bases: MySQL (local y AWS), PostgreSQL (Render), SQLite (pruebas). Flutter 3.47.1 instalado en `C:\Tecsup\2026-2\dev\flutter` con Android SDK 36.1 (licencias sin aceptar); sin Mac, así que iOS se genera pero no se compila aquí. Terraform y AWS CLI **no** instalados.
- API: base `/api/v1`. Respuestas `{ success, data, meta }` o `{ success:false, error:{ code, message, details } }`. Login `POST /auth/login` (`email`, `password`, `device_name`) devuelve `token`, `expires_at`, `user{roles[]}`; `POST /auth/refresh`; `GET /auth/me`; `POST /auth/logout`. Tras 3 fallos el login responde `retry_after` (429 `LOGIN_LOCKED`) y antes `attempts_left`. Listados paginados (`per_page` máx. 50). La web envía `Accept-Language`.
- Direcciones: API en Render `https://legrandhotel-api.onrender.com/api/v1`; local `http://localhost:8000/api/v1` (desde el emulador Android: `http://10.0.2.2:8000/api/v1`).
- Archivos que importan: `CLAUDE.md` (reglas del proyecto), `api/routes/api.php` (rutas y roles), `web/src/lib/api.ts` y `web/src/types.ts` (cliente y tipos a imitar), `web/src/styles.css` (tokens: tinta `#131416`, acento `#1b6c80`, IBM Plex Sans), `docs/movil/diseno-app-movil.md` y `docs/movil/pantallas.png` (diseño de la app), `infra/README.md` (arquitectura y costos AWS), `infra/terraform/*.tf`, `infra/terraform/terraform.tfvars.example`, `.github/workflows/deploy.yml`, `docs/migracion-servidor.md`, `docs/despliegue-render.md`, `render.yaml`, `api/docker/render/start.sh`, `docs/incidentes.md`.
- Cuentas de demostración: `admin@`, `recepcion@`, `almacen@`, `dev@legrandhotel.test`; la contraseña está en `DEMO_PASSWORD` de `api/.env` y **no se lee ni se copia** (el clasificador lo bloquea).

## 3. Decisiones
- Tomadas:
  - App en **Flutter** — lo pidió el usuario el 16/11; reemplaza la elección anterior del documento de diseño.
  - La app vive en `mobile/` dentro del monorepo y recibe la dirección de la API con `--dart-define=API_URL=…` (por defecto la de Render) — una sola app para local, Render y AWS.
  - El token se guarda en almacenamiento seguro (Keystore / Keychain), nunca en texto plano — sección 6 del diseño.
  - Pruebas de carga dentro de la red de Docker (`tests/k6/dentro.sh`) — el proxy de Docker Desktop en Windows rechazaba conexiones.
  - Cambio de rol de cualquier cuenta con contraseña obligatoria al pasar de cliente a personal; login con 3 intentos antes de la espera.
  - Render usa PostgreSQL (no ofrece MySQL gestionado); AWS usará RDS MySQL.
- Descartadas:
  - React Native + Expo — era la elección del diseño; el usuario pidió Flutter.
  - Pruebas de carga contra Render — 0,1 CPU y política de uso; se hacen en local y luego en AWS.
  - Subir de plan en Render para medir — no da resultados comparables.
  - Crear AWS sin dominio — el ALB necesita certificado ACM y este un dominio.

### A1 — informe de la auditoría de AWS (nada se aplicó; verificado: sin tfstate ni tfvars)
Huecos corregidos en `infra/**` y `.github/workflows/deploy.yml` (12 archivos): permisos S3 del rol de las instancias (GetObject deploy/* y mysql/*); confianza OIDC cambiada a `environment:production` (antes `ref:refs/heads/main` hacía fallar AssumeRole); rollback del deploy (ssm:GetParameter, solo si se subió imagen, ignora `:bootstrap`); worker sin `redis` fijo; `REDIS_HOST` solo si hay Redis; variables que faltaban en SSM (APP_NAME, APP_LOCALE=es, APP_TIMEZONE, SESSION_DRIVER, MAIL_MAILER, LOG_*, DB_TIMEOUT, BCRYPT_ROUNDS, RATE_LIMIT_* 5/3/60, AWS_EXECUTION_ENV); sin Redis la caché va a la base (`CACHE_STORE=database`) para que el bloqueo de login y los límites sean compartidos; `user_data` ahora corre `migrate --force`, `db:seed --class=RoleSeeder` y el seed completo solo si `RUN_SEED=true` y existe `DEMO_PASSWORD`; valores de `.env` entre comillas simples y arranque que aborta si faltan APP_KEY, DB_PASSWORD, API_IMAGE o BACKUP_BUCKET; RDS pasa a MySQL 8.4 (igual que local; la 8.0 sale de soporte estándar con cobro extra: dato no verificado, confirmar en consola); respaldo con cliente de la imagen `mysql:8.4` (mariadb no acepta `--set-gtid-purged`); primer despliegue sin salida resuelto con `asg_min=0` y `FIRST_DEPLOY=true`; `extra_frontend_origins` para CORS con la web de Render durante la migración (la app Flutter no necesita CORS: no envía `Origin`); outputs nuevos `github_variables`, `google_redirect_uri`, `ssm_prefix`.

Solo puede hacerlo el usuario: cuenta AWS + usuario IAM sin raíz; instalar Terraform y AWS CLI; dominio y DNS (`api_domain`→`alb_dns_name`, `web_domain`→`cloudfront_domain`); certificado ACM en us-east-1 validado por DNS; `terraform.tfvars` (dominios, ARN del certificado, `budget_email`) y confirmar la suscripción SNS; parámetros SSM bajo `/legrandhotel/prod/` (`APP_KEY` con `php artisan key:generate --show`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `DEMO_PASSWORD` si se siembra; `RUN_SEED=true` y luego `false`); redirect URI de Google `https://<api_domain>/api/v1/auth/google/callback`; GitHub: environment `production` limitado a `main`, secreto `AWS_DEPLOY_ROLE_ARN`, variables `ECR_REPOSITORY_URL`, `WEB_BUCKET`, `BACKUP_BUCKET`, `CLOUDFRONT_DISTRIBUTION_ID`, `ASG_NAME`, `API_URL`, `FIRST_DEPLOY`, opcional `DISCORD_WEBHOOK_URL`; migrar datos de Render (PostgreSQL) a RDS MySQL (no hay script); si la cuenta ya tiene proveedor OIDC de GitHub el apply falla (importar o quitar el recurso). Orden del primer despliegue: apply con `asg_min=0` → SSM y GitHub con `FIRST_DEPLOY=true` → push a main → apply con `asg_min=1` → `FIRST_DEPLOY=false`.
